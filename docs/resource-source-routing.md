# 资源安装方式与下载源规则

Kite 把“用什么方式安装”和“从哪个网络源获取”分成两层。资源卡负责声明安装内容和安装方式，应用设置只负责同一种安装方式内的源顺序。

## 安装方式优先级

新资源或既有资源改造时，按以下顺序选择第一个满足完整安装合同的方式：

1. 随应用交付的离线组件。
2. 上游官方维护的生态包，例如 npm、PyPI 或 APT 包。
3. 上游官方发布的、可固定版本并校验身份的架构制品。
4. 上游官方安装脚本。
5. 固定提交的源码安装。

“有 npm 就一定使用 npm”不是规则。生态包还必须满足目标架构可用、运行时版本兼容、入口完整、可验证版本、可卸载或可回滚。无法满足时，保留优先级更低但合同完整的方式。

安装方式在资源目录维护时确定，不在一次安装中从 npm 静默切换为脚本、发布包或源码。不同方式可能交付不同文件和版本，混用会破坏校验、回滚和卸载。

## 下载源顺序

设置中的“下载源优先级”是有序列表，不是测速结果。当前内置顺序为：

1. 华为云
2. npmmirror
3. 阿里云
4. 清华 TUNA
5. GitCode
6. 官方源

每个源只参与自己声明支持的生态：华为云覆盖 npm、PyPI、Ubuntu Ports；npmmirror 覆盖 npm；阿里云和 TUNA 覆盖 PyPI、Ubuntu Ports；GitCode 只参与资源卡明确列出的 Git 镜像；官方源覆盖 npmjs、PyPI、Ubuntu Ports、GitHub 或厂商直链。

资源卡不得再写入通用 npm、PyPI 或 Ubuntu 镜像地址。它只声明包名、版本、官方仓库和必要的厂商专用候选地址；通用地址由 `KiteResourceSourceCatalog` 集中维护。

## 切源事务

- NPM、PyPI 和 APT 每个源使用独立的尝试目录与缓存命名空间。
- 一次尝试失败后先删除该尝试产生的候选内容，再进入下一源。
- NPM 只有在安装命令非零退出时，才根据 DNS、连接、超时、HTTP 404、429 或 5xx 等错误判断来源不可用；成功请求日志中的可选包 404 不能推翻安装结果。
- 单步骤 NPM 卡片先在该源的候选目录执行卡片自身的命令与版本验证；候选不完整时删除候选并尝试下一源，通过后才发布正式目录。
- 摘要或固定提交不匹配、签名错误、依赖冲突、安装脚本错误和验证失败必须停止，不能用换源掩盖。
- 成功安装仍由资源安装事务统一验证并提交，源路由本身不直接发布正式目录。

## 版本检查

NPM 版本查询使用与安装相同的用户源顺序。第一个来源无法访问时才尝试下一来源。GitHub Release 和厂商专用版本接口没有等价公共镜像时保留官方查询，不伪造镜像覆盖。

## 资源卡维护检查

新增或更新资源卡时至少确认：

- 上游推荐的安装方式和目标 ARM64 Linux 兼容性。
- 包管理器的主包及平台依赖在目标源中是否完整。
- 固定版本、摘要、提交或包管理器锁定信息是否足以验证身份。
- 安装失败是否只留下有明确事务归属的候选目录。
- `managedCommands`、版本探针、验证步骤、卸载和保留目录是否对应同一安装方式。
- 通用镜像是否已从 manifest 删除，由集中源目录注入。
