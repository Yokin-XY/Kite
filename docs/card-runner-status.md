# 卡片运行器施工账本

更新日期: 2026-06-10

## 当前能成立的链路

- 手动创建卡片后, 表单里的动作会保存成卡片 `recipe` 数组。
- 点击启动时, 只要 `recipe` 数组里有步骤, 就进入顺序执行器。
- 执行顺序按数组原始顺序走: 谁在前面谁先执行。
- `open_web` 可以放在第一步, 不会被 Ubuntu 预检挡住。
- `shell` 和 `terminal` 只有执行到对应步骤时才准备 Ubuntu。
- 每次启动会创建一个运行实例, 状态不写回卡片模板。
- 每个步骤已有通用字段 `surfaceMode`: 自动, 打开面板, 后台静默。
- 每张卡片已有启动配置 `launch.openInstance`: 从首页启动时是否打开独立实例任务。
- 已有独立卡片运行 Activity, 通过 Android document task 支持多开。
- 桌面快捷方式申请只存本机配置, 不写入卡片 JSON; 快捷方式点击后按卡片 ID 创建新的运行实例并进入独立任务。

## 现在还只是框架的部分

- 首页卡片是主要报告入口, 不再另做最小运行面板。
- 运行实例有网页, 终端, 报告, 概览的表面模型, 但展示仍主要复用首页卡片和已有网页/终端壳。
- 通知点击回到运行实例还没接。
- 运行实例目前主要在内存里, App 进程被杀后的恢复还没做。
- 终端隐藏运行可以创建会话并发送预设命令, 但交互型终端仍建议打开面板。

## 优先级

1. 真机验证手动卡片启动: 先测纯网页, 再测 `python3 --version`, 再测网页在前的混合流程。
2. 真机验证桌面快捷方式: 点击快捷方式后是否进入独立最近任务, 多次点击是否多开。
3. 接通知: 后台执行完成或失败后通知用户, 点击通知打开对应运行实例。
4. 做持久化: 保存最近运行实例和报告索引, 让重启 App 后还能找回。
5. 清理旧入口: 保留一个顺序执行器, 去掉临时兼容分支。

## 风险提示

- 当前通过了本地构建, 还没有完成真机端到端验证。
- `shell` 成功/失败依赖桥接层返回的运行报告。
- 后台静默适合网页或普通命令, 不适合需要人工输入的终端步骤。
- 桌面快捷方式使用系统 pinned shortcut, 不同桌面可能会弹确认或不支持自动创建。
