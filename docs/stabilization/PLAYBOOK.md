# Kite 主线稳定化执行母板

## 总目标

在不继续扩张 X11 和完整浏览器能力的前提下，把现有 Kite 主线规整成行为一致、
状态可信、生命周期可控、便于继续扩展的稳定产品。

本任务采用“会话分支、代码单主线”模式：不同 Codex 会话负责不同阶段，但所有
已验收成果都按顺序提交到本地 `main`。不为阶段建立并行 Git 开发分支。

## 固定原则

1. 不以拆文件数量代替职责转移。
2. 不新增平行状态源；继续使用现有 Store 和运行时事实源。
3. 用户动作必须立即进入处理中，最终状态必须由状态拥有者确认。
4. 普通状态变化只更新可见控件，不重建整页或运行显示面。
5. 页面生命周期、运行实例生命周期和底层进程生命周期必须分开。
6. 每个阶段必须有独立本地提交；禁止把多个阶段混成一个提交。
7. 每个阶段完成声明必须有测试、构建、静态检查或真机证据。

## 阶段梯队

### S1 基线与行为合同

- 修复已经失真的静态检查，使检查真实表达现有行为合同。
- 为后续重构建立可执行的行为回归安全网。
- 不修改用户可见业务流程，不进行页面迁移。

验收标准：

- [ ] 运行车道静态检查通过，且不依赖已经失效的源码精确形状。
- [ ] 第一批行为测试覆盖动作路由、停止确认或导航合同中的真实高风险点。
- [ ] 相关单测通过。
- [ ] Debug APK 构建通过。
- [ ] `PROGRESS.md` 写明提交节点、证据和下一阶段入口。

### S2 导航与返回

- 建立统一目标页和返回策略。
- 现有入口逐步经过统一导航，不一次性迁移所有页面。

### S3 动作编排

- 统一启动、打开、停止、卸载和重试入口。
- 以进程管理作为第一条完整样板链。

### S4 状态投影

- 收口首页、资源列表、详情和安装向导的显示状态。
- Store 更新后只对可见位置做局部投影。

### S5 显示面与生命周期

- 规整终端、报告、WebView、后台任务和页面销毁边界。
- 补齐内存压力下的可恢复释放和运行保护。

### S6 模块化与扩展

- 把页面职责真正移出 `MainActivity`。
- 终端快捷面板注册化，完成性能与发布回归。

## 每阶段执行流程

1. 读取本文件和 `PROGRESS.md` 的当前恢复指针。
2. 写清当前阶段目标、验收和直接依赖。
3. 小步实现，每形成独立成果立即验证并本地提交。
4. 对照验收清单，不以“代码写完”代替完成。
5. 回写进度和关键决策，为下一会话留下准确入口。

## Git 边界

- 所有阶段顺序提交到本地 `main`。
- 只显式暂存当前阶段文件，不使用 `git add .`。
- 不提交构建物、设备日志、截图、附件或用户已有未提交改动。
- 未经用户再次确认，不推送 GitHub、不发布版本。
