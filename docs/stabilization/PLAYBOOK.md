# Kite 主线稳定化执行母板

## 总目标

在不继续扩张 X11 和完整浏览器能力的前提下，把现有 Kite 主线规整成行为一致、
状态可信、生命周期可控、便于继续扩展的稳定产品。

本任务采用“会话分支、代码单主线”模式：不同 Codex 会话负责不同阶段，但所有
已验收成果都按顺序提交到本地 `main`。不为阶段建立并行 Git 开发分支。

## 固定原则

1. 不以拆文件数量代替职责转移。
2. 不新增平行状态源；继续使用现有 Store 和运行时事实源。
3. 用户动作必须立即进入处理中，最终状态必须由状态拥有者确认。
4. 普通状态变化只更新可见控件，不重建整页或运行显示面。
5. 页面生命周期、运行实例生命周期和底层进程生命周期必须分开。
6. 每个阶段必须有独立本地提交；禁止把多个阶段混成一个提交。
7. 每个阶段完成声明必须有测试、构建、静态检查或真机证据。

## 五个方向任务

执行方式：不再按会话分工。当前会话在本地 `main` 上按 D1 到 D5 连续推进，完成一个方向并提交、验收后自动进入下一个方向。

### D1 导航与返回规则统一

当前负责会话：本会话

- 建立统一 `Destination + BackPolicy` 合同。
- 收口系统 back、顶部返回、页面恢复和运行任务返回。
- 现有 `show*()` 渐进接入统一导航入口，不改变页面视觉。

验收标准：

- [x] 导航矩阵覆盖根页面、子页面、运行窗口、显示面和外部回跳。
- [x] 系统 back 与顶部返回读取同一份返回策略。
- [x] 页面恢复使用同一目标模型，不再维护平行映射。
- [x] 普通导航不重建无关运行显示面，不修改状态事实。
- [x] 导航合同测试、全量单测和 Debug 构建通过。
- [x] OnePlus 8T 走通主要返回路径，页面视觉无变化。

### D2 动作编排统一

- 统一获取、启动、打开、停止、卸载和重试命令。
- 页面只提交动作意图，不自行拼接执行流程。

验收标准：

- [ ] 首页、编辑页和运行面上的同类卡片动作经过同一动作入口。
- [ ] 资源获取、打开、停止、卸载、重试经过统一资源动作入口。
- [ ] 动作入口不直接阻塞执行重活，运行事实仍由既有 Store 拥有。
- [ ] 同一意图只创建或更新一个目标实例，不因页面来源重复执行。
- [ ] 动作合同、全量单测、Debug 构建和 OnePlus 8T 关键路径通过。

### D3 状态投影和局部更新统一

- 将资源投影模式扩展到首页、运行窗口、安装向导和进程管理。
- 页面只消费事实并局部更新，不复制长期状态。

### D4 生命周期和资源预算收口

- 区分页面、运行实例、显示面和底层进程生命周期。
- 统一卡片、终端、WebView 和 AI 后台服务的准入与回收边界。

### D5 真正的功能模块与扩展点

- 让 `MainActivity` 最终只保留应用外壳和导航职责。
- 合并进程管理重复页面，终端快捷面板改为可注册动作。

## 全局实施顺序

以下顺序由母任务统筹，不等同于五个会话方向：

1. 固定行为基线并补验收矩阵。
2. 收口导航和返回。
3. 以进程管理验证新模式。
4. 迁移资源安装和首页卡片。
5. 迁移终端、报告和 Web 显示面。
6. 优化内存、启动速度、APK 体积和扩展面板。

## 每方向执行流程

1. 读取本文件和 `PROGRESS.md` 的当前恢复指针。
2. 写清当前阶段目标、验收和直接依赖。
3. 小步实现，每形成独立成果立即验证并本地提交。
4. 对照验收清单，不以“代码写完”代替完成。
5. 回写进度和关键决策，自动进入下一个就绪方向。

## Git 边界

- 所有方向的已验收成果顺序提交到本地 `main`。
- 只显式暂存当前阶段文件，不使用 `git add .`。
- 不提交构建物、设备日志、截图、附件或用户已有未提交改动。
- 未经用户再次确认，不推送 GitHub、不发布版本。
