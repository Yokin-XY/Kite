# 状态与生命周期

## 状态拥有者

Kite 不允许页面长期保存业务事实副本。主要事实源如下：

| 事实 | 拥有者 | 页面如何使用 |
| --- | --- | --- |
| 卡片实例、步骤、报告、窗口绑定 | `CardRunStore` | 通过运行投影生成 UiState |
| 资源安装计划和处理中状态 | `KiteResourceInstallStore` | 资源页和向导消费同一快照 |
| 已安装资源 | `KiteResourceRegistry` 与安装快照 | 资源卡片投影安装结果 |
| 终端会话 | `TerminalSessionController` | 终端显示面只绑定目标会话 |
| owner 与进程存活 | PRoot telemetry / RuntimeHealth | 运行管理消费统一拓扑 |
| 浏览器认证会话 | `BrowserAuthSessionStore` | 认证协调器恢复和交付回调 |

状态拥有者写事实并发出轻量信号；页面收到信号后重新读取快照，只更新相关控件。

## 用户动作

```text
用户点击
-> 页面立即显示处理中
-> Application 接收动作
-> Platform 执行
-> 状态拥有者确认成功、失败或继续等待
-> 页面投影最终状态
```

处理中状态表示动作已经被接收，不代表后台已经成功。超时或来源不完整时必须保留可解释状态，不能悄悄恢复为初始按钮。

## 四类生命周期

### 页面生命周期

页面进入、离开或重建只影响可见绑定和订阅。普通返回只隐藏当前任务，不能据此停止卡片、终端、资源获取或后台任务；页面销毁同样不能被解释为用户要求关闭实例。

### 显示面生命周期

报告、终端、WebView 和实验 X11 都是实例窗口中的显示面。关闭手动窗口只释放目标窗口；流程窗口由步骤拥有，可重置但不独立删除。

### 实例生命周期

一次卡片启动是一个逻辑实例。首页卡片启动和资源 Open 都必须先由编排器创建真实实例，再以
`autoStart=false` 打开同一代显示任务；页面不能在打开后自行补建第二份实例事实。实例拥有固定步骤窗口、手动窗口、终端和精确 owner。用户显式关闭实例或从最近任务划除实例任务时，统一向状态拥有者提交关闭意图，先把状态写为 `Stopping`，再按拓扑回收子孙，最终单向进入 `Stopped`。

### 进程生命周期

PRoot 命令通过结构化 owner 标识来源。进程关闭在后台串行执行发现、TERM、复核、KILL 和稳定静默确认。瞬时残留只进入后台补偿，不允许把已经关闭的旧实例恢复为运行中。

## 代次与迟到结果

同一个卡片可以反复启动，因此所有异步结果都必须对应 `instanceId + generation`。实例显示任务把二者同时写入 Intent extra 和唯一 data URI，任务匹配、通知和关闭入口都按同一身份校验。旧代次的停止、终端、任务划除或页面回调不能覆盖新代次，也不能误停新进程；旧任务发现同名新代次时只关闭自己的显示面，不能换绑。

应用主任务被系统划除时，服务会先把仍存在的每个实例显示任务的精确身份提交给统一关闭协调器，再结束这些显示任务。显示页面只负责关闭窗口；运行停止、资源取消和临时事实清理由对应状态拥有者完成。

## 内存与后台

- `Activity` 或 `Fragment` 销毁不等于任务失败。
- WebView 等可恢复显示资源可以在内存压力下回收。
- 活跃任务必须经过既有租约、准入和回收策略，页面不能直接杀进程。
- 用户明确停止、系统内存回调和应用进程退出是三种不同事件。

## 页面同步规则

- 事实变化只更新相关卡片、按钮、步骤或报告片段。
- 页面不可见时只记录待校准，返回前台后从状态拥有者读取快照。
- 周期扫描仅用于纠偏，不是主要同步机制。
- 不通过整页重建、连续 Toast 或重新导航表达普通进度。

## 资源获取向导

资源获取向导是安装计划的显示面，不是安装计划的状态拥有者。它只消费
`KiteResourceInstallStore` 的计划快照和 `CardRunStore` 的运行快照，并遵守以下规则：

- 用户点击获取并被接受后，状态拥有者先写入 `PREPARING` 计划和同代向导根，再在后台单飞解析依赖；计划成功后以同一计划代次原子切换到 `ACTIVE`，页面不等待或执行计划解析。
- `PREPARING` 和 `ACTIVE` 都投影为可点击的“获取中”。普通返回只隐藏向导，资源首页或详情再次点击时复入同一代向导；不会因为返回而把资源写成不可用。
- 详情取消、向导显式关闭或向导任务从最近任务划除都会提交同一代取消意图。取消在每个环境的生命周期门内重新校验资源目标、计划代次和向导代次，清理未完成子实例及临时事实，并最后清除计划；迟到的旧准备或旧取消结果不能覆盖新一轮获取。
- 安装完成后由状态拥有者清理计划；显示页面只关闭显示任务，不直接删除安装或运行事实。
- 开始和权限等待等动作必须有 Accepted、Deferred 或 Rejected 回执，拒绝后撤销乐观状态。
- 资源项或计划步骤事实不足时统一显示校准态，不得同时显示“已完成”和“等待中”。
- 队列只负责展示安装进度，不通过行点击或额外报告按钮跳转显示面；失败时只保留显式的残留清理与重试入口。
