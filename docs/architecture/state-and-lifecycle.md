# 状态与生命周期

## 状态拥有者

Kite 不允许页面长期保存业务事实副本。主要事实源如下：

| 事实 | 拥有者 | 页面如何使用 |
| --- | --- | --- |
| 卡片实例、步骤、报告、窗口绑定 | `CardRunStore` | 通过运行投影生成 UiState |
| 资源安装计划和处理中状态 | `KiteResourceInstallStore` | 资源页和向导消费同一快照 |
| 已安装资源 | `KiteResourceRegistry` 与安装快照 | 资源卡片投影安装结果 |
| 终端会话 | `TerminalSessionController` | 终端显示面只绑定目标会话 |
| owner 与进程存活 | PRoot telemetry / RuntimeHealth | 运行管理消费统一拓扑 |
| 浏览器认证会话 | `BrowserAuthSessionStore` | 认证协调器恢复和交付回调 |

状态拥有者写事实并发出轻量信号；页面收到信号后重新读取快照，只更新相关控件。

## 用户动作

```text
用户点击
-> 页面立即显示处理中
-> Application 接收动作
-> Platform 执行
-> 状态拥有者确认成功、失败或继续等待
-> 页面投影最终状态
```

处理中状态表示动作已经被接收，不代表后台已经成功。超时或来源不完整时必须保留可解释状态，不能悄悄恢复为初始按钮。

## 四类生命周期

### 页面生命周期

页面进入、离开或重建只影响可见绑定和订阅。离开页面不停止卡片、终端或后台任务。

### 显示面生命周期

报告、终端、WebView 和实验 X11 都是实例窗口中的显示面。关闭手动窗口只释放目标窗口；流程窗口由步骤拥有，可重置但不独立删除。

### 实例生命周期

一次卡片启动是一个逻辑实例。实例拥有固定步骤窗口、手动窗口、终端和精确 owner。关闭实例时先把状态写为 `Stopping`，再按拓扑回收子孙，最终单向进入 `Stopped`。

### 进程生命周期

PRoot 命令通过结构化 owner 标识来源。进程关闭在后台串行执行发现、TERM、复核、KILL 和稳定静默确认。瞬时残留只进入后台补偿，不允许把已经关闭的旧实例恢复为运行中。

## 代次与迟到结果

同一个卡片可以反复启动，因此所有异步结果都必须对应 `instanceId + generation`。旧代次的停止、终端或页面回调不能覆盖新代次，也不能误停新进程。

## 内存与后台

- `Activity` 或 `Fragment` 销毁不等于任务失败。
- WebView 等可恢复显示资源可以在内存压力下回收。
- 活跃任务必须经过既有租约、准入和回收策略，页面不能直接杀进程。
- 用户明确停止、系统内存回调和应用进程退出是三种不同事件。

## 页面同步规则

- 事实变化只更新相关卡片、按钮、步骤或报告片段。
- 页面不可见时只记录待校准，返回前台后从状态拥有者读取快照。
- 周期扫描仅用于纠偏，不是主要同步机制。
- 不通过整页重建、连续 Toast 或重新导航表达普通进度。
