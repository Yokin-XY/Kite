# 设置中心架构

## 用户结构

设置首页保持四个稳定分组，具体能力进入八个二级页：

| 分组 | 二级页 | 主要内容 |
| --- | --- | --- |
| 个性化 | 外观与语言 | 主题、应用语言 |
| 使用方式 | 应用行为 | 返回现场、最近任务行为 |
| 使用方式 | 终端与工作台 | 终端默认字号、终端主题和工作界面说明 |
| 使用方式 | 浏览器与登录 | WebView、系统浏览器认证和 Android 网络边界 |
| 系统 | 权限与文件 | Android 权限、共享投放区 |
| 系统 | 运行环境 | Android 运行底座、运行管理和资源中心边界 |
| 其他 | 实验功能 | 尚未进入稳定承诺的显式开关 |
| 其他 | 帮助与关于 | 版本、日志和诊断入口 |

大分组不随内部模块增减而变化。新增普通能力优先进入已有二级页；只有出现新的用户目标且无法合理归类时，才增加二级页或顶层分组。

## 先判断能力属于谁

“可以配置”不等于“由设置中心保存”。新增入口前先按下表确认事实拥有者：

| 能力性质 | 状态拥有者 | 设置页表达 |
| --- | --- | --- |
| 应用级长期偏好 | `SettingsGateway` | 开关或选择项 |
| 功能默认值 | 对应功能的偏好 API，例如 `TerminalUiPreferences` | 选择项，直接读写同一份偏好 |
| Android 权限 | Android 系统与现有权限投影 | 真实摘要 + 系统设置入口 |
| 运行、资源或安装事实 | `RuntimeBootstrapGateway`、`CardRunStore`、资源 Store/Registry | 轻量摘要 + 管理页入口 |
| 单次任务或实例参数 | Recipe、运行实例或功能编辑器 | 不进入全局设置 |
| 未稳定能力 | 原功能状态拥有者 | 仅在实验功能页出现并明确提示 |
| 诊断动作 | 日志或维护功能自身 | 按需动作入口，不做周期扫描 |

禁止为了显示一个设置项再复制一份布尔值、安装状态、权限结论或运行状态。页面只提交用户意图和显示拥有者投影。

## 主题是统一环境，不是页面颜色表

主题偏好由 `SettingsGateway` 持有，当前包括：

- `themeMode`：`SYSTEM`、`LIGHT`、`DARK`。
- `themeColor/backgroundColor`：基础颜色选择。
- `themeStyleKey`：组件样式注册键。

`ThemeEnvironmentGateway` 是应用级唯一读取入口。它把偏好与 Android 当前明暗状态交给 `KiteTheme.resolveEnvironment()`，得到有效明暗、语义颜色和组件样式。页面不得直接读取 `kite_theme`、自行判断系统明暗或按样式名写条件分支。

颜色与组件样式分层：

- `ThemeTokens` 表达页面背景、表面、文字、边框、主色和状态色。
- `ThemeComponentStyle` 表达圆角、间距、描边和层级。
- `ThemeStyleDefinition` 登记一套组件样式，`ThemeScope` 允许首页、资源、设置、编辑、运行和终端在中央合同内继承或覆盖局部形态。

新增一套颜色时，只增加颜色定义或选择项；新增一套界面形态时，只在 `KiteTheme.styleDefinitions` 登记样式并补充本地化名称。设置页自动消费注册表，普通页面继续读取语义字段，不需要逐页增加新主题分支。当前 `standard` 是第一套默认样式，只表达现有结构，不锁定最终品牌配色。

终端 ANSI 色板继续由终端模块独立校准。终端选择“跟随应用”时使用 `ThemeEnvironment` 的有效明暗；显式亮色/暗色仍可覆盖，但切换只能重置当前画布颜色，不得重连会话。

## 入口语义

`SettingsCatalog` 使用固定入口类型描述交互：

- `Toggle`：直接切换现有布尔偏好。
- `Choice`：从稳定选项中选择并写入现有偏好。
- `Navigation`：进入 Kite 内部管理页面。
- `SystemSettings`：进入 Android 系统页面。
- `Status`：只读轻量事实摘要。
- `Action`：用户主动触发的一次性动作。
- `Info`：说明稳定边界，不执行探测。

成熟度分为 `Stable`、`Experimental` 和 `DebugOnly`。实验能力不能混进稳定说明，也不能成为稳定路径的前置条件。

## 导航与恢复

设置二级页使用类型化 `AppDestination`，普通二级页返回设置首页。可从多个入口进入的管理页面使用上下文返回，并保留安全 fallback。设置目录的滚动位置属于纯 UI 状态，可在 Activity 范围保存；偏好和运行事实不进入该状态。

从 Android 系统权限页或日志 Activity 返回时，应回到原设置二级页。返回不能依赖页面标题、URL 字符串或 Activity 历史偶然成立。

## 更新与压力边界

设置页面允许：

- 进入页面或从系统页返回时做一次显式轻量刷新。
- 订阅现有 `StateFlow` 并只更新受影响行。
- 打开现有管理页、系统设置或按需诊断动作。

设置页面禁止：

- 在构建、绑定或滚动中扫描文件、数据库、网络、运行时或 Manifest。
- 使用定时器或整页刷新同步状态。
- 重建终端、WebView、报告或运行窗口。
- 把 `showCardRunSurface(...)` 或 `refreshResourceScreenIfVisible()` 当成普通设置更新手段。

## 新增能力的最小流程

1. 确认用户目标、能力性质和真实状态拥有者。
2. 选择现有二级页、入口类型和成熟度。
3. 在 `SettingsCatalog` 增加稳定元数据；动态事实仍由对应 Fragment/Screen 轻量投影。
4. 固定文字同时加入默认与英文资源；运行输出、路径、命令和日志原文保持原样。
5. 为目录唯一性、导航合同、状态写入和页面投影补充聚焦测试。
6. 运行单测、Lint、本地化、架构与压力门禁，并在 OnePlus 8T 验证可见路径和返回链。
