# 当前架构决策

本文件只保存已经进入当前主线的长期决定。任务过程、试错记录和真机日志不属于架构决策。

## 模块化单体

Kite 先在现有 Gradle 模块内建立 App Shell、Feature、Application、Platform 和 Foundation 边界。只有依赖方向稳定且确有独立构建价值时，才考虑继续拆 Gradle 模块。

## 单一事实源

安装事实由资源 Store 和 Registry 拥有，运行事实由 `CardRunStore` 和运行时遥测拥有。页面不能复制一份长期业务状态，也不能自行宣布安装或停止成功。

## 单向动作链

页面提交意图，Application 编排，Platform 执行，状态拥有者确认，Projector 生成 UiState。用户点击应立即得到处理中反馈，最终结果必须来自真实事实。

## 生命周期分离

页面、显示面、运行实例和底层进程拥有不同生命周期。页面离开不停止任务，用户关闭实例才递归回收该实例产生的窗口、终端和进程。

## 运行实例使用显式拓扑

运行管理按 `instanceId + generation + owner` 建立父子关系，不通过名称或评分猜测进程归属。无法证明归属的进程保持未归属。

## 资源渠道不同，生命周期统一

资源可以来自内置包、下载、Git、npm、apt 或官方脚本，但统一经过获取、安装、验证、提交和清理。只有验证完成后才能登记为已安装。

## 认证使用官方系统浏览器

普通和本地网页由 WebView 承载；OAuth/SSO 授权交给系统浏览器。Kite 只桥接标准请求和回调，不伪造浏览器身份，不为单个 Provider 写登录协议特判。

## 容器网络服从 Android 应用网络

PRoot、终端和其中运行的 CLI 保持 Kite 的 Android 应用 UID，并使用共享宿主网络栈。Kite 不识别或复制 VPN 应用、节点、规则和包名单；Android 根据用户对 Kite 的按应用设置决定流量走 VPN 还是普通网络。容器 DNS 只采用 Android 当前默认网络提供的服务器，并随默认网络变化更新；系统没有可用 DNS 时不得擅自切换到公共 DNS。系统浏览器使用浏览器自己的 UID 和网络规则。

## 实验能力不进入稳定承诺

浏览器自动化和 X11 可以保留实现并继续研究，但默认稳定路径、发布说明和正式验收不得依赖它们。实验能力必须在入口和文档中明确提示。

## 设置中心是能力索引

设置首页只拥有稳定分类、入口类型、成熟度和导航目标，不成为全局事实 Store。应用偏好继续由 `SettingsGateway` 持有；终端默认值、运行准备、资源安装和 Android 权限分别由原拥有者持有。设置页只投影轻量摘要或提供管理入口，详细规则见[设置中心架构](settings.md)。

## 多来源页面使用上下文返回

运行管理等可从多个正式入口进入的页面使用 `BackPolicy.Contextual`。调用方登记准确返回目标；没有上下文时回到合同中的安全父级。目标页不得通过标题、参数或 Activity 历史猜测来源。

## 界面位置与业务事实分离

滚动位置等短期界面状态可以由 Activity 级 UI 状态持有，用于返回时恢复现场；它不能包含偏好、权限、安装或运行事实，也不能触发后台探测。

## 终端主题使用确定性色板

终端明暗主题从 Kite 自有的不可变标准色板生成，再覆盖 Termux 当前默认色表。页面不得把进程级可变的 `TerminalColors.COLOR_SCHEME` 反向捕获为基础色。基础 ANSI 16 色按明暗背景分别校准，扩展色保持 xterm 标准索引；主题切换只重置当前会话颜色和局部控件，不重连会话或重建分页。

## 终端快捷动作声明输入副作用

终端快捷页继续通过 `TerminalPanelActionRegistry` 扩展。每个动作显式声明执行后保留还是清理实时预输入，统一执行入口先运行 handler，再由终端 host 兑现输入副作用。页面不得通过控制字符串内容猜测 Ctrl+C、Enter 等动作语义；主题、分页和动作反馈只更新现有终端控件。

## 主题按语义和组件治理，不按页面扩张

主题偏好由 `SettingsGateway` 持有，`ThemeEnvironmentGateway` 是应用级唯一读取入口。`KiteTheme` 统一解析跟随系统/亮色/暗色和外观选择；页面不直接读取 SharedPreferences，也不自行判断 Android 明暗。

颜色方案只替换稳定语义角色的值；界面风格只替换标准组件配方。页面网格、字体层级、触控底线、导航结构和业务行为属于固定设计基础，不随主题包切换。普通功能页不拥有 `HOME/RESOURCE/SETTINGS` 等页面级主题作用域；局部差异通过组件变体、表面层级或终端/Web/X11 等特殊内容适配器表达。

当前实现以 `ThemeCommand`、`ThemeSelection`、`ThemeCatalog` 和 `ThemeEnvironment` 作为中间规则协议。设置和未来命令入口不再发送裸颜色字段，页面级 `ThemeScope` 已移除，页面间距与触控底线进入固定基础，组件外观进入组件配方。旧颜色键仅作为兼容迁移输入；完整规则见[主题系统规范](theme-system.md)。

## 主题命令与接收组件通过中间协议解耦

主题上游只表达“改变模式、选择颜色方案、导入受控种子、选择风格包、恢复默认”等意图，下游只消费已归一化的语义颜色、固定基础、组件配方和特殊内容策略。未知目录键统一回退，任何功能页都不能成为主题规则解释者。

`KiteTheme` 和主题协议保持 Android-free，Android 系统明暗、SharedPreferences 与 Bundle 分别由 Platform/UI 适配器接入。这样命令端、设置端或接收组件任一侧大改时，另一侧只需继续遵守同一协议，不需要同步页面字段和字符串特判。

## 固定界面本地化，内容证据保持原文

标题、按钮、状态、空态、标准分类和可访问性描述属于 Kite 固定界面，统一由 Android 资源键解析。资源名称/简介/海报、原始 JSON、终端输出、日志、协议诊断和第三方错误属于内容或证据，保持来源原文。

本地化显示文字不能成为业务协议：资源分类使用 tab/section ID，动作和状态使用 Intent、Phase 或枚举。旧模块若只能提供展示文字，只允许在单一兼容适配边界转换，不能继续向新页面扩散文字比较。

## 二级页面向首页和设置的现有语言收口

首页与设置是当前标准页面基准。普通二级页面复用完整 `ThemeEnvironment`、固定文字层级、容器配方、标准顶栏和真实图标；终端正文、WebView、X11、报告、资源海报等特殊内容只统一外层边界。

UI 收口不得新增页面事实源、轮询、整页刷新或运行探测。无 Manifest、无导航、无 Fragment 事务且无测试引用的旧页面直接删除，不为清理而重新包装成新能力。

## 运行管理使用范围导航和应用进程树

运行管理一级页只表达三个范围：全部运行项、真实运行卡片和未归属进程。卡片是命令与生命周期归属边界，不是应用名称；全部和未归属只是导航范围，不伪装成卡片。

三个二级范围复用同一工作负载/进程树投影。PRoot 根据遥测会话、父生命周期和 Linux 作业边界自动生成
`workloadScopeId`；同名进程只有身份相同时才归组，异名子孙只要继承同一作用域就保持在同组。未归属只表示
没有 owner，仍按工作负载作用域组织。运行脚手架单独归入运行基础，不为具体应用写名称特判。

活动目录枚举成功后，可以在短暂创建宽限后淘汰整个已经消失的强身份会话；目标会话自身不稳定时不能宣布退出，无关会话不稳定不阻塞它。文件事件先重放，活动注册表最后收敛。所有后台运行项在启动边界注入标准运行身份并由 PRoot 子树继承，不把通用 `sleep`、`bash` 名称作为归类依据。数据层始终保留工作负载作用域，二级页仅在同一作用域有两个及以上可见成员时显示可展开组，单成员直接显示进程行。

同一 PID 的数据源冲突按身份强度处理：PRoot 强生命周期记录优先于未归属运行根，真实 owner 根仍作为整体控制入口保留。不得让弱观察记录遮蔽 PRoot 身份并把可控子进程降级成兼容只读项。

卡片与进程菜单只展示现有能力。危险动作必须二次确认，并继续由运行状态拥有者确认最终结果；页面不自行宣布停止成功。卡片图标复用配方图标协议，进程图标解析和跨范围搜索保留为独立后续能力。

## Agent 模型库使用分组、供应商和模型三层合同

Agent 会话输入区只展示当前模型；点击后在同一个紧凑弹层内用“供应商、模型”两个纵向折叠框完成选择：先展开供应商，选定后原地收起并展开该供应商的模型，不切换页面，也不显示图标、数量或说明文字。后台模型库使用“分组 → 供应商 → 模型”结构：`全部` 是虚拟汇总，`免费` 是只读系统分组，自定义分组删除后只清除供应商归属，不删除供应商或模型。

供应商名称、URL、模型 ID、模型名称、API Key、来源类型、默认选择、权限目录、推理目录、工作模式目录和工作模式草稿默认值统一由 `AgentProviderCatalogStore` 持有，UI 与运行时只经过 `AgentProviderCatalogApi`。API Key 使用 Android Keystore 主密钥加密，只能在发送准备调用栈中短暂解密；公开目录、页面状态、日志和普通 JSON 只保留凭据是否存在。`AgentModelLibraryStore` 只保存分组、供应商是否进入会话选择器和逐模型显示名称等展示偏好，不复制连接事实。

三种来源采用不同且固定的更新入口：用户自定义由 Kite 直接保存；无需登录的免费来源随 Kite 版本提供首次本地快照，之后只在用户于供应商管理页主动下拉时由 Adapter 扫描并原子替换该免费来源，刷新失败继续保留旧快照；官方登录来源不参加刷新扫描，只在官方登录成功并取得模型目录后保存一个可切换版本。打开供应商管理页和普通会话加载都只读取 Kite 目录。旧版曾直接写入 Agent 原生文件的用户 Provider 只进行一次有标记迁移，不能成为长期回填通道。

所有来源统一区分“显示名称”和“模型 ID”。显示名称只用于 Kite UI，自定义、免费和官方来源都可以修改；模型 ID 是传给 Agent/Provider 的稳定引用，显示名称覆盖只能替换选择项的 `name/description`，不能改变 `value`、默认模型、草稿选择、恢复或适配器匹配。自定义 Provider 延续名称、URL、API Key 和模型 ID 的原生配置编辑；免费与官方属于系统管理来源，只开放 Kite 显示名称、会话可见性和已有默认选择，不开放 URL、API Key、模型 ID、删除或来源改写。官方登录状态和登录/退出入口继续由官方账号管理器持有。

官方账号声明的真实模型组通过显式 `modelGroupIds` 映射到稳定的 Kite 官方来源 ID；免费来源使用 Agent 公布的真实分组。系统来源别名以“Kite 来源 ID + 原始协议模型值”为键，自定义来源兼容原生短模型 ID。不得用显示名称、账号标题或模型文案猜测来源或请求标识。

后台默认模型与当前输入草稿是两个选择作用域，但共同读取同一 Kite 目录。无论空白草稿、运行中会话还是上一轮完成后的下一轮，模型、权限、推理和已适配的工作模式入口都继续显示；用户可在发送前反复修改，任何选择都不提前写 Agent。点击发送后才冻结草稿，从 Kite 读取 Provider 配置，由 Adapter 执行必要写入、重连或原生 thread 创建，再应用模型、推理、权限、工作模式和消息。工作模式保留原生 ID，显示翻译与预设目录留在对应 Agent 的 Adapter；ACP `session.setMode` 仍是支持时的优先执行通道。免费模型选择不得反向伪造用户 Provider，官方版本不得被免费扫描覆盖。

## Agent 会话归档保持 Kite 标记与原生摘要双事实边界

Kite 归档保存 Provider ID、Session ID、归档时间和最近一次来源核验状态，用于控制 Kite 会话列表中的显示；Agent 继续拥有会话标题、工作目录、消息、真实存在性和永久删除能力。来源核验状态只能由完整成功的 `session/list` 目录更新：目录中的归档 ID 标记为可用，完整目录中缺失的归档 ID 标记为已删除。分页不完整、列表失败、Agent 未运行或不支持列表时不得把记录误判为删除。

归档管理页把 Kite 标记与原生摘要做受控投影。可用记录显示 Agent 原生摘要；确认缺失的记录显示“源会话已删除”；尚未完成可靠核验的记录显示“尚未确认”。后两类记录不能通过“恢复”清除归档标记，必须明确反馈当前不可恢复。确认已删除的记录只允许删除 Kite 归档元数据；尚未确认的记录只有在同一 Provider 的真实删除能力可安全调用时才请求原生删除，否则文案必须明确只清理 Kite 记录。

归档内容使用统一长按选择合同。会话和异常记录以 Session ID 作为唯一选择键；项目头只是其当前已归档子会话的集合选择入口，显示未选、部分和全选三态。项目元数据和未归档会话不进入批量恢复/删除集合；空项目不显示项目选择器。选择模式恢复必须二次确认，所有删除都必须二次确认。正常会话永久删除继续由 Agent 成功结果确认；对项目会话的集合操作绝不删除项目、工作目录或未归档会话。批量操作全部成功后退出选择，部分失败则保留未完成项和选择状态。

Agent 会话重命名是可选原生能力，不是 Kite 显示别名。`AgentSessionCapabilities.rename` 只表示当前 Connection/Adapter 能通过 Agent 官方协议或原生管理 API 修改真实标题；页面使用稳定 Session ID 提交请求，只在原生成功后更新列表投影。不支持的 Agent 隐藏重命名入口；禁止写 Kite 假标题、直接改第三方会话文件或在 UI 按 Agent 名称特判。OpenCode 当前通过官方 `PATCH /session/{id}` 会话 API 适配，不使用仅修改 Kite 展示的替代方案。

会话抽屉的更多菜单使用能力投影：归档始终是 Kite 标记并可直接执行；重命名只在原生 rename 可用时显示；删除只在原生 delete 可用时显示，当前正在使用的会话禁用删除，其余删除必须二次确认。菜单和选择态采用 Agent 页面固定中性视觉，不消费 Kite 旧青蓝强调色。

设置摘要和管理页必须以同一组 Kite 归档标记为总量口径。Agent 未运行、不支持列表、读取失败、源会话已删除和真正没有归档内容是不同状态；UI 只消费 Runtime/Adapter 与 Store 的既有事实，不在行绑定或页面绘制期间扫描文件、探测进程或执行网络检查。

## Agent 会话语义与三车道运行底座在进程创建前衔接

Agent 注册和资源清单可以声明 `runtimeGuarantees` 与 `runtimeGuaranteeEvidence`，`AndroidAgentRecipeRuntime` 只负责把这些事实连同结构化 argv、工作目录和环境提交给统一 `ManagedRuntimeLaunchPlanner`。Planner 必须在创建业务进程前给出唯一结果：Host Ready、单次 PRoot 计划或明确 Blocked；Host 业务进程启动后不得因失败再静默重跑一份 PRoot 任务。后台运行依赖使用同一运行保证字段，但事实继续由 `BackgroundRuntimeRegistry` 持有。

运行底座只决定进程创建前的执行车道，不拥有 Agent 会话语义。会话固定 Agent、草稿和模型、恢复、请求发送、状态文案、rename/delete 的能力判断、stdin、超时、错误反馈和回调顺序继续由 Kite Agent SDK、Runtime 与专用 Adapter 持有。官方账号动作不伪造运行保证；会话管理命令需要完整 Linux 时可使用统一 FULL_LINUX PRoot Provider，但不能借此改写用户可见操作语义。
