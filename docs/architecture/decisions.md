# 当前架构决策

本文件只保存已经进入当前主线的长期决定。任务过程、试错记录和真机日志不属于架构决策。

## 模块化单体

Kite 先在现有 Gradle 模块内建立 App Shell、Feature、Application、Platform 和 Foundation 边界。只有依赖方向稳定且确有独立构建价值时，才考虑继续拆 Gradle 模块。

## 单一事实源

安装事实由资源 Store 和 Registry 拥有，运行事实由 `CardRunStore` 和运行时遥测拥有。页面不能复制一份长期业务状态，也不能自行宣布安装或停止成功。

## 单向动作链

页面提交意图，Application 编排，Platform 执行，状态拥有者确认，Projector 生成 UiState。用户点击应立即得到处理中反馈，最终结果必须来自真实事实。

## 生命周期分离

页面、显示面、运行实例和底层进程拥有不同生命周期。页面离开不停止任务，用户关闭实例才递归回收该实例产生的窗口、终端和进程。

## 运行实例使用显式拓扑

运行管理按 `instanceId + generation + owner` 建立父子关系，不通过名称或评分猜测进程归属。无法证明归属的进程保持未归属。

## 资源渠道不同，生命周期统一

资源可以来自内置包、下载、Git、npm、apt 或官方脚本，但统一经过获取、安装、验证、提交和清理。只有验证完成后才能登记为已安装。

## 认证使用官方系统浏览器

普通和本地网页由 WebView 承载；OAuth/SSO 授权交给系统浏览器。Kite 只桥接标准请求和回调，不伪造浏览器身份，不为单个 Provider 写登录协议特判。

## 容器网络服从 Android 应用网络

PRoot、终端和其中运行的 CLI 保持 Kite 的 Android 应用 UID，并使用共享宿主网络栈。Kite 不识别或复制 VPN 应用、节点、规则和包名单；Android 根据用户对 Kite 的按应用设置决定流量走 VPN 还是普通网络。容器 DNS 只采用 Android 当前默认网络提供的服务器，并随默认网络变化更新；系统没有可用 DNS 时不得擅自切换到公共 DNS。系统浏览器使用浏览器自己的 UID 和网络规则。

## 实验能力不进入稳定承诺

浏览器自动化和 X11 可以保留实现并继续研究，但默认稳定路径、发布说明和正式验收不得依赖它们。实验能力必须在入口和文档中明确提示。

## 设置中心是能力索引

设置首页只拥有稳定分类、入口类型、成熟度和导航目标，不成为全局事实 Store。应用偏好继续由 `SettingsGateway` 持有；终端默认值、运行准备、资源安装和 Android 权限分别由原拥有者持有。设置页只投影轻量摘要或提供管理入口，详细规则见[设置中心架构](settings.md)。

## 多来源页面使用上下文返回

运行管理等可从多个正式入口进入的页面使用 `BackPolicy.Contextual`。调用方登记准确返回目标；没有上下文时回到合同中的安全父级。目标页不得通过标题、参数或 Activity 历史猜测来源。

## 界面位置与业务事实分离

滚动位置等短期界面状态可以由 Activity 级 UI 状态持有，用于返回时恢复现场；它不能包含偏好、权限、安装或运行事实，也不能触发后台探测。

## 终端主题使用确定性色板

终端明暗主题从 Kite 自有的不可变标准色板生成，再覆盖 Termux 当前默认色表。页面不得把进程级可变的 `TerminalColors.COLOR_SCHEME` 反向捕获为基础色。基础 ANSI 16 色按明暗背景分别校准，扩展色保持 xterm 标准索引；主题切换只重置当前会话颜色和局部控件，不重连会话或重建分页。

## 终端快捷动作声明输入副作用

终端快捷页继续通过 `TerminalPanelActionRegistry` 扩展。每个动作显式声明执行后保留还是清理实时预输入，统一执行入口先运行 handler，再由终端 host 兑现输入副作用。页面不得通过控制字符串内容猜测 Ctrl+C、Enter 等动作语义；主题、分页和动作反馈只更新现有终端控件。

## 主题按语义和组件治理，不按页面扩张

主题偏好由 `SettingsGateway` 持有，`ThemeEnvironmentGateway` 是应用级唯一读取入口。`KiteTheme` 统一解析跟随系统/亮色/暗色和外观选择；页面不直接读取 SharedPreferences，也不自行判断 Android 明暗。

颜色方案只替换稳定语义角色的值；界面风格只替换标准组件配方。页面网格、字体层级、触控底线、导航结构和业务行为属于固定设计基础，不随主题包切换。普通功能页不拥有 `HOME/RESOURCE/SETTINGS` 等页面级主题作用域；局部差异通过组件变体、表面层级或终端/Web/X11 等特殊内容适配器表达。

当前实现以 `ThemeCommand`、`ThemeSelection`、`ThemeCatalog` 和 `ThemeEnvironment` 作为中间规则协议。设置和未来命令入口不再发送裸颜色字段，页面级 `ThemeScope` 已移除，页面间距与触控底线进入固定基础，组件外观进入组件配方。旧颜色键仅作为兼容迁移输入；完整规则见[主题系统规范](theme-system.md)。

## 主题命令与接收组件通过中间协议解耦

主题上游只表达“改变模式、选择颜色方案、导入受控种子、选择风格包、恢复默认”等意图，下游只消费已归一化的语义颜色、固定基础、组件配方和特殊内容策略。未知目录键统一回退，任何功能页都不能成为主题规则解释者。

`KiteTheme` 和主题协议保持 Android-free，Android 系统明暗、SharedPreferences 与 Bundle 分别由 Platform/UI 适配器接入。这样命令端、设置端或接收组件任一侧大改时，另一侧只需继续遵守同一协议，不需要同步页面字段和字符串特判。

## 固定界面本地化，内容证据保持原文

标题、按钮、状态、空态、标准分类和可访问性描述属于 Kite 固定界面，统一由 Android 资源键解析。资源名称/简介/海报、原始 JSON、终端输出、日志、协议诊断和第三方错误属于内容或证据，保持来源原文。

本地化显示文字不能成为业务协议：资源分类使用 tab/section ID，动作和状态使用 Intent、Phase 或枚举。旧模块若只能提供展示文字，只允许在单一兼容适配边界转换，不能继续向新页面扩散文字比较。

## 二级页面向首页和设置的现有语言收口

首页与设置是当前标准页面基准。普通二级页面复用完整 `ThemeEnvironment`、固定文字层级、容器配方、标准顶栏和真实图标；终端正文、WebView、X11、报告、资源海报等特殊内容只统一外层边界。

UI 收口不得新增页面事实源、轮询、整页刷新或运行探测。无 Manifest、无导航、无 Fragment 事务且无测试引用的旧页面直接删除，不为清理而重新包装成新能力。

## 运行管理使用范围导航和应用进程树

运行管理一级页只表达三个范围：全部运行项、真实运行卡片和未归属进程。卡片是命令与生命周期归属边界，不是应用名称；全部和未归属只是导航范围，不伪装成卡片。

三个二级范围复用同一工作负载/进程树投影。PRoot 根据遥测会话、父生命周期和 Linux 作业边界自动生成
`workloadScopeId`；同名进程只有身份相同时才归组，异名子孙只要继承同一作用域就保持在同组。未归属只表示
没有 owner，仍按工作负载作用域组织。运行脚手架单独归入运行基础，不为具体应用写名称特判。

活动目录枚举成功后，可以在短暂创建宽限后淘汰整个已经消失的强身份会话；目标会话自身不稳定时不能宣布退出，无关会话不稳定不阻塞它。文件事件先重放，活动注册表最后收敛。所有后台运行项在启动边界注入标准运行身份并由 PRoot 子树继承，不把通用 `sleep`、`bash` 名称作为归类依据。数据层始终保留工作负载作用域，二级页仅在同一作用域有两个及以上可见成员时显示可展开组，单成员直接显示进程行。

同一 PID 的数据源冲突按身份强度处理：PRoot 强生命周期记录优先于未归属运行根，真实 owner 根仍作为整体控制入口保留。不得让弱观察记录遮蔽 PRoot 身份并把可控子进程降级成兼容只读项。

卡片与进程菜单只展示现有能力。危险动作必须二次确认，并继续由运行状态拥有者确认最终结果；页面不自行宣布停止成功。卡片图标复用配方图标协议，进程图标解析和跨范围搜索保留为独立后续能力。
