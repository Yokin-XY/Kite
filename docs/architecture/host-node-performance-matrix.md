# 宿主 Node 性能矩阵

## 证据边界

本矩阵是 2026-07-31 在 OnePlus 8T（`3f8bbaad`）上完成的既有证据。Host 与 PRoot 使用同一 Node、同一负载和相同轮数，
每个测点三轮。它证明当前代表性 Node 合同的收益，不等同于模型首 token、npm 插件或原生 addon 兼容。

可复现入口：

```powershell
.\scripts\host-node-pressure-benchmark.ps1 -Serial 3f8bbaad -Rounds 3
```

## 已得结论

1. 当前 JS 小文件和 Worker 合同没有发现宿主快速通道反向退化，p50 优势为 25.3%～61.5%；
2. 并发不是越高越快，不能把占满核心写成全局策略；
3. 100 个独立 Node 进程在 Host 仍需约 9.04 秒，这是进程模型成本；
4. 受管 Node 子级继续递归走 Host，真正 Linux 外部命令保持 PRoot；
5. Node 主路径不接温热 PRoot Runner，也不使用共享 Node VM 改变进程隔离。

## 重跑规则

RF210 不重复本矩阵。只有 Node、rootfs、兼容层代次、正式入口或被测合同发生变化时，才重跑受影响场景；新增 Python 或原生
Provider 使用自己的矩阵，不能借用 Node 数据宣称收益。
