# Android/NDK 原生能力 Provider

## 定位

原生 Provider 负责 Android 已能直接、稳定兑现的通用能力。它不是“把所有 Linux 命令重写一遍”，也不是根据资源名称绕开
PRoot。只有能够用结构化参数完整表达权限、输入、取消、结果和副作用的能力才进入本车道。

适合原生化的方向包括网络下载、摘要、受控文件操作、APK 安装、Android 网络事实、Keystore 和经过安全约束的归档处理。
需要完整 Linux 路径、权限、链接、shell 或 ELF 语义的任务继续进入 PRoot。

## 能力请求

原生请求必须是枚举化能力和结构化参数，例如：

- 能力类型与版本；
- 输入来源、目标句柄或受控路径；
- 权限要求；
- 超时、取消和进度出口；
- 原子性、校验和失败清理要求；
- owner、run 与结果身份。

Provider 不接受任意 shell 文本，也不从 `curl`、`sha256sum` 等命令名反推用户想要什么。现有 Recipe 或资源安装流程必须显式
提交能力请求。

## 第一项能力：下载与 SHA-256

选择它作为样板，是因为它通用、可测量，并能使用 Android 网络栈继承当前应用 UID、VPN、私有 DNS 和证书策略。

第一版需要覆盖：

1. HTTPS 下载到同目录临时文件；
2. 流式 SHA-256，不把大文件整体读入内存；
3. 可选期望摘要，失败时不替换正式目标；
4. 成功后的原子替换或明确降级；
5. 超时、取消、网络中断和空间不足；
6. 临时文件清理与可解释结果；
7. 进度只写运行状态，不驱动整页刷新。

断点续传和重试必须显式设计：只有服务器能力、临时文件身份和 Range 响应可验证时才续传；不能把不确定响应追加到旧文件。

## 文件与归档能力

文件复制、移动、权限和受控删除必须接入现有文件保护、更新锁和备份边界，不建立第二套资源安装事务。

归档是后续独立能力，不与下载样板捆绑。需要防止：

- `../`、绝对路径和 zip-slip；
- 符号链接或硬链接逃逸；
- 解压炸弹、文件数和尺寸失控；
- 不可表达的 Linux owner、mode、xattr；
- 空间不足后的半成品污染。

当资源依赖完整 tar、链接或权限语义时，明确选择 PRoot，而不是用不完整原生实现冒充兼容。

## 复用现有 Android 能力

PackageInstaller、网络状态、Android 权限、Keystore 等现有实现应通过薄 Provider 适配进入能力目录。Provider 不复制安装状态、
资源登记或密钥内容；相应状态继续由现有模块持有。

## 状态与显示面

原生能力执行仍属于同一个 CardRun 或后台 owner：

- Provider 写入实际 `native_*` 车道和稳定能力原因；
- 进度、结果、失败和取消通过原运行事件进入状态拥有者；
- 页面只局部绑定状态；
- 原生能力没有终端时使用报告或安装向导显示面，不创建虚假终端会话。

## 发布门

- 能力参数和权限边界可机器验证；
- 与现有 PRoot 实现在共同语义范围内做结果对照；
- 覆盖失败清理、取消、进程/线程泄漏和大文件压力；
- 用户网络环境由 Android 正常决定，不硬编码公共 DNS 或绕过 VPN；
- 没有资源 ID、应用名或当前样例特判。
