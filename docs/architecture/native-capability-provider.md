# Android/NDK 原生能力 Provider

## 定位

原生 Provider 负责 Android 已能直接、稳定兑现的通用能力。它不是“把所有 Linux 命令重写一遍”，也不是根据资源名称绕开
PRoot。只有能够用结构化参数完整表达权限、输入、取消、结果和副作用的能力才进入本车道。

适合原生化的方向包括网络下载、摘要、受控文件操作、APK 安装、Android 网络事实、Keystore 和经过安全约束的归档处理。
需要完整 Linux 路径、权限、链接、shell 或 ELF 语义的任务继续进入 PRoot。

## 能力请求

原生请求必须是枚举化能力和结构化参数，例如：

- 能力类型与版本；
- 输入来源、目标句柄或受控路径；
- 权限要求；
- 超时、取消和进度出口；
- 原子性、校验和失败清理要求；
- owner、run 与结果身份。

Provider 不接受任意 shell 文本，也不从 `curl`、`sha256sum` 等命令名反推用户想要什么。现有 Recipe 或资源安装流程必须显式
提交能力请求。

## 第一项能力：下载与 SHA-256

选择它作为样板，是因为它通用、可测量，并能使用 Android 网络栈继承当前应用 UID、VPN、私有 DNS 和证书策略。

第一版需要覆盖：

1. HTTPS 下载到同目录临时文件；
2. 流式 SHA-256，不把大文件整体读入内存；
3. 可选期望摘要，失败时不替换正式目标；
4. 成功后的原子替换或明确降级；
5. 超时、取消、网络中断和空间不足；
6. 临时文件清理与可解释结果；
7. 进度只写运行状态，不驱动整页刷新。

断点续传和重试必须显式设计：只有服务器能力、临时文件身份和 Range 响应可验证时才续传；不能把不确定响应追加到旧文件。

## RF310a 已实现边界

`network.download_sha256` 已作为标准 `ANDROID_NATIVE` Provider 落地。请求字段为：

- `url`：只接受无用户信息、无 fragment 的 HTTPS URL；
- `destination`：只映射调用方显式提供的受控容器根，不接受 Android 物理路径；
- `maxBytes`：必填，下载前和流式写入时双重限制；
- `expectedSha256`：可选 64 位十六进制摘要；
- `connectTimeoutMs`、`readTimeoutMs`、`maxAttempts`、`retryDelayMs`、`replaceExisting`：有界可选参数。

Provider 只生成计划，不联网、不建目录、不写 Store。执行器使用 Android `HttpURLConnection`，临时文件与目标位于同一目录，流式
计算 SHA-256，`fd.sync()` 后优先 `ATOMIC_MOVE`；平台不支持时才显式记录非原子降级。摘要失败、取消、HTTP 失败和空间不足都不
替换正式目标，并要求临时文件清理成功。

第一版不发送 Range，每次重试从空临时文件开始；意外 206、重定向降级到 HTTP、未知参数和目录逃逸均失败关闭。进度回调只是
运行层信号，正式 RF310b 调用方必须节流后写入原 `CardRun`，不得直接驱动页面刷新。

RF310a 的 Debug 真机入口固定下载 RFC Editor 的 18,504 字节样本，不接受外部 URL/路径。它证明 Android 应用网络栈、摘要、
原子发布、错误摘要保留旧文件和取消清理；不等于资源安装链已经迁移，资源迁移归 RF310c。

## RF310b Recipe 与 Run 合同

正式 Recipe 使用显式步骤，不把 `curl` 文本或资源身份翻译成原生能力：

```json
{
  "type": "native_capability",
  "action": "network.download_sha256",
  "params": {
    "url": "https://example.com/archive.tar.zst",
    "destination": "/workspace/cache/archive.tar.zst",
    "maxBytes": "536870912",
    "expectedSha256": "64位十六进制摘要"
  }
}
```

第一版参数值全部是字符串，由对应 Provider 做类型、范围和未知字段校验。运行端把请求声明为 `ANDROID_NATIVE`，并关闭隐式
PRoot 回退；不支持或受阻时直接写可解释失败，不能执行另一份 shell 任务。

能力在既有 `RunOrchestrator -> AndroidRecipeExecutor` 链中执行。进度按 1 MiB 或 500 ms 节流，经运行事件写回同一个
`CardRunStore`；结果使用报告显示面，不创建 `runId`、`terminalSessionId` 或进程 owner。停止和重启即使没有进程绑定也会
调用原生运行端，取消阻塞 I/O，并在清理临时文件后确认。

RF310b 只建立通用 Recipe/Run 接口。资源获取尚未自动转换，更新锁、备份和安装状态拥有者也没有改变；这些属于 RF310c。

## RF310c1 资源预取边界

资源编译器只把以下 `download` 步骤提升到原生车道：

- 位于受管动作开头，不依赖更早的 shell 副作用；
- 只有一个无变量的静态 HTTPS URL；
- 目标是 `$install_root` 下可验证的安全相对路径；
- 清单显式声明正数 `maxBytes`。

原生步骤实际写入资源缓存，而不是活动安装根。成功后，后续 PRoot shell 才获取每资源更新锁，在既有事务内移动缓存、执行其余
安装步骤、验证并提交；失败继续走原回滚。动态 URL、多镜像、无尺寸上限或依赖架构 shell 变量的步骤继续由
`KiteResourceInstallPlanCompiler` 编译到 PRoot。

这一边界不是按 Kimi、Hermes、OpenCode 等资源名称选择。清单只声明事实，统一编译器根据结构化安全门决定；普通 shell 也会在
准备阶段把 `proot_shell / shell_command_requires_proot` 写入同一 `CardRun`，避免残留上一原生步骤的车道事实。

## RF310c2 对照与压力结论

OnePlus 8T 上用同一固定 HTTPS 样本交替运行原生 Provider 与 PRoot `curl + sha256sum` 各 3 轮。原生 p50 为 534 ms，
PRoot p50 为 654 ms，当前样本降低 18.3%。这只证明固定设备、网络时段与该下载链的额外成本差异，不作为所有 URL、文件尺寸
或网络环境的统一性能承诺。

失败边界同时通过两层证据：真机不可连接端点验证有限重试后的失败清理；确定性连接夹具在首轮输出部分字节后中断，验证第二轮从
空临时文件开始，不拼接残片。真机另完成 2,020,420 字节流式下载、摘要与原子发布，单测覆盖 32 MiB 流式负载和空间不足前置
拒绝。动态 URL、多镜像、无尺寸上限和依赖 shell 变量的输入不是遗留漏做，而是明确保留给 PRoot 的兼容范围。

RF310 至此完成。RF320 若原生化文件复制、移动或删除，必须继续使用同一结构化能力车道，并复用资源更新锁、备份与状态拥有者；
不得把 Android 文件 API 变成绕过事务保护的旁路。

## RF320a 受控文件能力

第一版文件 Provider 将复制、移动和删除拆成三个固定能力。每个可见根分别授予 `READ`、`CREATE`、`REPLACE`、`REMOVE`，路径
匹配时更具体的根优先。生产接线可以让整个工作区可读或创建，但只让缓存等临时根拥有 `REMOVE`，从能力层阻止任意 Recipe 删除
用户工作区。

Provider 逐段拒绝路径穿越、空段和既有符号链接。执行器只处理普通单文件：复制写入目标同目录临时文件，关闭并同步文件后再原子
发布；移动只接受平台原子移动，不支持时失败关闭；删除必须来自显式 `REMOVE` 根且不递归。取消发生在流式复制中时，先关闭文件流
再删除临时文件，正式目标保持不变。

这套授权不是资源更新事务的替代品。RF320b 先接入同一 Recipe/Run；RF320c 只能迁移缓存等非活动状态。活动安装根仍由资源级锁、
单份备份、验证和回滚脚本拥有，旧 View/`ResourceTransactionCoordinator` 不重新进入正式链。

RF320b 已把文件 Provider 接入既有 `native_capability` 分发器。下载能力明确不支持时才继续选择文件能力；参数受阻和执行失败不会
触发另一条业务路径。文件进度、结果和取消写回同一 `CardRun` 的 `android_native` 事实与报告显示面，不创建终端、进程 owner
或新的 Store。生产上下文只让 `/workspace/.kf/cache` 拥有删除权限，整个工作区不因可读写而自动获得破坏权限。

## RF320c 资源边界与真机结论

资源清单与安装编译器审计没有发现可脱离事务的文件步骤。现有移动、删除和安装都修改活动安装根或命令链接，必须继续由资源级锁、
单份备份、验证和回滚脚本持有。本阶段“没有迁移资源步骤”是安全结论，不是用资源 ID 白名单挑选样本，也不代表通用文件 Provider
没有完成。

OnePlus 8T 的固定 16 MiB 对照中，原生复制 p50 为 56 ms，带 PRoot 启动的等价复制与落盘同步 p50 为 355 ms，当前测点减少
84.2%。同一 `CardRun` 的 copy→move→delete 正式链为 172 ms，只观察到 `android_native`，没有终端或业务进程。工作区删除
权限在 Provider 阶段被拒绝，探针目录最终不存在。上述时间只适用于本次固定设备和负载。

后续如果资源合同出现明确的缓存内复制、移动或清理步骤，可以直接编译为本能力；只要目标涉及活动安装根，就仍需先解决同一事务
内的锁与回滚，而不是把文件操作提前到锁外。

## RF330a ZIP 安全解包边界

`archive.extract_safe` 第一版只开放普通文件和目录 ZIP。请求必须显式给出压缩包、目标、压缩包大小、条目数、总输出、单文件、
目录深度和膨胀比上限。tar/tar.gz、链接、设备节点以及 owner、mode、xattr 保真继续走 PRoot；rootfs 的完整 Linux 解包器不作为
本能力的安全替代。

执行器先读取 ZIP 中央目录，再打开每个条目内容。这样才能可靠识别 Unix 符号链接；只使用流式本地头会丢失该元数据，已经由反例
测试否决。路径同时拒绝绝对路径、盘符、反斜杠、空段、`.`、`..`、超深/超长和重复条目。所有文件先落到目标同级唯一暂存
目录，成功后原子发布整个目录；任何失败或取消都清理暂存，正式目标在完成前不存在。

## 文件与归档能力

文件复制、移动、权限和受控删除必须接入现有文件保护、更新锁和备份边界，不建立第二套资源安装事务。

归档是后续独立能力，不与下载样板捆绑。需要防止：

- `../`、绝对路径和 zip-slip；
- 符号链接或硬链接逃逸；
- 解压炸弹、文件数和尺寸失控；
- 不可表达的 Linux owner、mode、xattr；
- 空间不足后的半成品污染。

当资源依赖完整 tar、链接或权限语义时，明确选择 PRoot，而不是用不完整原生实现冒充兼容。

## 复用现有 Android 能力

PackageInstaller、网络状态、Android 权限、Keystore 等现有实现应通过薄 Provider 适配进入能力目录。Provider 不复制安装状态、
资源登记或密钥内容；相应状态继续由现有模块持有。

## 状态与显示面

原生能力执行仍属于同一个 CardRun 或后台 owner：

- Provider 写入实际 `native_*` 车道和稳定能力原因；
- 进度、结果、失败和取消通过原运行事件进入状态拥有者；
- 页面只局部绑定状态；
- 原生能力没有终端时使用报告或安装向导显示面，不创建虚假终端会话。

## 发布门

- 能力参数和权限边界可机器验证；
- 与现有 PRoot 实现在共同语义范围内做结果对照；
- 覆盖失败清理、取消、进程/线程泄漏和大文件压力；
- 用户网络环境由 Android 正常决定，不硬编码公共 DNS 或绕过 VPN；
- 没有资源 ID、应用名或当前样例特判。
