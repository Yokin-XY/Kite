# Ubuntu 模拟态纲领（运行时统一方针）

> 2026-09-21 · 状态：已确认方针（用户与开发者共同确认）
> 本文件是所有运行时工作的总方针：目标、方法论、态度与确定性锚点。工程分期见 [ubuntu-fast-lane-plan](../plans/ubuntu-fast-lane-plan.md)；本纲领变更时该计划须同步修订。

## 一、问题与目标

**痛点**：PRoot 慢通道导致启动慢、运行慢，且慢是结构性的（ptrace 每个系统调用停两次）。

**目标**（按序）：

1. **确定性与稳定性**：快速通道上的程序行为可预测、可复现，不因手机品牌和系统版本漂移。
2. **整个 Ubuntu 上通道**：全部常规 Linux 程序默认运行在快速通道上，更新免疫——不为单个工具做单独车道。
3. **PRoot 保底常在**：补不住的命令自动降级且遥测可见，永不静默崩溃；随收编面扩大，PRoot 份额逐步压缩。

## 二、视角与态度

### 视角：系统级优先

一切修复从"整个系统"出发。地基级方案优先（改公共文件，所有程序受益）；单程序方案只作过渡，且必须回答"这个修法对系统意味着什么"。

### 态度：95/5 原则

- **95%（走地基的程序）**：一次性收编，官方更新零适配。
- **5%（绕地基直连内核的程序）**：两种处理，都接受——
  - 当 **bug**：列进雷库，慢慢想，不着急；
  - 当 **特性**：提前预知并优雅降级（探测 → 走退路 → 明确提示"不支持"），**而不是崩溃**。
- 分界线不是缺陷，是分界线：线内一次性收编，线外当 bug 修或走保底。

## 三、确定性锚点

> **唯一锚点：安卓全国统一的保底动作集**（bionic 基础集，AOSP 定义）。所有安卓 App 依赖它活着，任何厂商砍它则自家 App 全灭——因此它跨品牌、跨版本稳定。

由锚点推出三条纪律：

1. **不猜厂商规则**：各厂 seccomp 门禁细节不统一，逐厂探测是死路。
2. **不逐台适配**：不为某台设备写特判；补丁只依赖保底动作集。
3. **双机验收**：一加 8T（开发）+ 魅族 18（验收）都通过才算通用；单机通过不算。

## 四、模拟态架构：三层 + 二分

**"Ubuntu 模拟态"**：外观是完整 Ubuntu，地基层（loader、glibc、兼容层）已被替换为"安卓原生兼容版"。内核不换——保底动作集正是内核提供的。

```
第 1 层  地基收编（雷源头文件补丁）  ← 主力：确定性 100%，静态可验证
第 2 层  兼容垫片（PLT hook/版本化符号）← 辅助：管路径翻译（已建成）
第 3 层  PRoot 保底               ← 底线：不行就走慢通道（已建成）
```

**二分法**（所有程序只分两种）：

| 类别 | 占比 | 处理 |
|---|---|---|
| 走 glibc 地基的动态程序 | ~95% | 统一入口 + 补丁版 glibc 自动覆盖，更新免疫 |
| 绕地基直发 syscall 的（Rust/Go/静态） | ~5% | 探测器抓出 → 单点文件补丁或退保底 |

**为什么改地基＝包上层**：几乎所有 Ubuntu 程序都站在 glibc 上。改这一个文件，效果上等于包住整个 Ubuntu——程序怎么升级都得踩这块地基。这就是"不用管软件更新"的实现原理。

## 五、实现手段优先级

| 优先级 | 手段 | 确定性 | 状态 |
|---|---|---|---|
| 1 | **雷源头文件补丁**（改我们自己带的 glibc / 程序模块，让危险动作走自带退路） | 100%（静态、可校验、零运行时开销、跨机型） | 首选，当前主攻 |
| 2 | 兼容垫片（libkite-glibc-compat.so 版本化符号 + JS 预载钩子） | 高（覆盖函数调用路径） | 已建成 |
| 3 | 运行时保镖 | **低，实证不可靠** | 降级为雷探测器 |
| 4 | PRoot | 高 | 已建成 |

**ptrace 保镖的结论（2026-09-21 实证）**：PTRACE_SYSCALL 全量跟踪的入口/出口交替判定，在多线程 + 信号频繁 + 厂商内核环境下频繁错位（单轮实测 142 次）；节奏时序跨机型不可预测，修不完也验证不完。**永远不作为通关依赖**。它的新岗位是**雷探测器**：诊断某程序越界动作的专用工具，见第七节闭环。

## 六、收编闭环（以后每个新程序都走这条流水线）

```
新程序上快速通道
   ↓
雷探测器（tracer DIAG 模式）跑一遍，列出全部越界动作
   ↓
雷库登记（syscall 号 + 来源文件 + 降级路径）
   ↓
雷源头文件补丁 + 回归测试固化
   ↓
双机型验收（一加 8T + 魅族 18）
   ↓
所有程序永久受益，PRoot 份额相应缩小
```

成本一次性、可沉淀；不存在无限排查。

## 七、初始雷库（2026-09-21，App 域 untrusted_app 实测）

| 雷号 | 动作 | 来源 | 自带退路（补丁方式） |
|---|---|---|---|
| 99 | set_robust_list | 我们带的 glibc | glibc 视为不支持 → 跳过（robust list 可选） |
| 278 | getrandom | 我们带的 glibc | glibc 视为不支持 → 读 /dev/urandom |
| 293 | rseq | 我们带的 glibc | glibc 视为不支持 → 禁用 rseq（tunable 亦可关） |
| 437 | openat2 | openclaw fs-safe 模块（Rust 直发） | 返回 ENOSYS → rustix 自动降级 openat |

配套事实：root 域（su 10285 同 uid）同链路 8 秒稳定 readyz=200（复现脚本 `/data/local/tmp/ptest-app-lane2.sh`）；App 域死因全部归结为上述 4 雷与 ptrace 错位，无其他未知雷。

## 九、远期特性（记录意图，非承诺）

1. **自有 Linux 发行版**：地基（loader + 补丁版 glibc + 兼容层）已自有，内容层（rootfs 软件包）可按需重组。发行版的本质是组装而非源码重写——当地基收编完成后，"自己的 Linux"成本可控。
2. **多发行版 / 多架构支持**：模拟态骨架对发行版不敏感；aarch64 之外的架构不在当前承诺内。
