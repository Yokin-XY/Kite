# Kite 产品正式化与 v0.0.8 候选任务手册

## 当前恢复指针

- 当前任务：开发与本地验收已完成
- 当前阶段：等待发布授权
- 当前出口：用户明确授权后，把候选版本定为 `0.0.8` 并执行正式 Release 门、Git 和 GitHub Release
- 版本策略：开发期间保持 `versionName=0.0.4`、`versionCode=4`；不发布中间版本。全部发布门通过后，候选正式版本为 `0.0.8`，发布前再依据真实范围确认。

## 用户目标

把目前散落在设置页、功能页面、隐藏诊断页和系统权限入口中的“设置属性”统一规整。设置中心既能容纳后续能力增加和细化，又不能复制运行、资源、权限等状态事实。完成设置中心后继续做一轮产品正式化收尾，最后把多个完成项合并为一个正式版本，而不是每个小改动单独发布。

## 总体红线

1. 设置目录只拥有分类、标题、说明、稳定性和导航元数据，不拥有业务状态。
2. `SettingsGateway` 继续只拥有应用级偏好及轻量系统状态投影；终端、运行、资源和权限事实留在各自拥有者。
3. 页面构建、绑定和滚动路径不得执行文件扫描、数据库查询、网络健康检查、运行时探测或 manifest 解析。
4. 普通设置变化只更新受影响控件；不得触发 `showCardRunSurface(...)`、`refreshResourceScreenIfVisible()`、终端重连或 WebView 重载。
5. Android 权限只能显示真实状态并打开系统入口，不得伪造成 Kite 本地开关。
6. 浏览器自动化和 X11 必须与稳定能力分开并明确标记实验状态。
7. 固定用户界面文字必须同时进入中文和英文资源；终端输出、日志原文和协议数据保持原样。
8. 未经用户再次明确要求，不执行 Git commit、push、tag、GitHub Release 或版本号修改。

## 发布梯队

### T001 [P0] 设置能力目录与回归安全网

- 问题证据：`SettingsScreen.kt` 以固定顺序手工构建七个大卡片；`AppNavigator.kt` 只有 `Settings` 和 `ThemeSettings` 两个设置目标；现有测试主要覆盖旧页面和控制器，没有能力分类、稳定性和目标映射合同。
- 解法：先建立设置分类、入口类型、稳定性和类型化目标的纯 Kotlin 合同及测试；补充压力边界静态断言，确保目录不承担动态探测和业务写入。
- 验收标准：
  - [x] 设置分类和入口类型拥有穷举测试。
  - [x] 稳定、实验和 Debug 入口的可见性规则有测试。
  - [x] 每个目录项都有唯一 ID、资源标题、所属分类和类型化目标。
  - [x] 聚焦单测和 `git diff --check` 通过。
- 依赖：无。

### T002 [P1] 设置首页与导航地基

- 问题证据：设置页当前同时承担首页索引、偏好控件和系统入口，新增能力只能继续追加硬编码卡片；只有主题拥有二级页面。
- 解法：把设置首页改成稳定分类索引；增加类型化二级设置目标、统一页面骨架和返回合同；沿用现有 Kite 主题、卡片、间距和底部导航结构。
- 验收标准：
  - [x] 设置首页按“个性化、使用方式、系统、其他”分组。
  - [x] 外观与语言、应用行为、终端与工作台、浏览器与登录、权限与文件、运行环境、实验功能、帮助与关于都有稳定入口。
  - [x] 所有二级页返回设置首页，页面恢复合同有测试。
  - [x] 导航不重建终端、WebView 或运行显示面。
- 依赖：T001。

### T003 [P2] 现有应用偏好迁移

- 问题证据：主题、语言、浏览器模式、恢复现场、最近任务显示、通知和投放区目前平铺在一个页面；浏览器说明在固定两行副标题组件中被截断。
- 解法：把现有偏好迁入对应二级页面；继续使用 `SettingsGateway` 和既有 Effect；说明型对话框使用可完整阅读的正文样式。
- 验收标准：
  - [x] 主题、语言、恢复现场、最近任务行为不变。
  - [x] 通知和投放区仍由系统事实刷新，不复制本地状态。
  - [x] 浏览器认证说明可以完整显示。
  - [x] 现有 Settings Gateway/Controller 测试保持通过。
- 依赖：T002。

### T004 [P2] 功能默认值与实验能力分离

- 问题证据：终端字号和终端主题持久化在 `TerminalUiPreferences`，只在终端现场可见；`BrowserRuntimeMode` 把稳定的系统浏览器认证和实验性的自动化浏览器放在同一选择器。
- 解法：设置中增加终端默认值入口，终端现场继续保留快捷控制并共用同一状态拥有者；稳定浏览器说明与实验自动化入口分离，但不复制浏览器模式事实。
- 验收标准：
  - [x] 设置和终端现场修改同一份字号与主题偏好。
  - [x] 自动化浏览器只在实验功能页出现，并显示实验提示。
  - [x] 稳定浏览器登录页不把实验能力写成正式承诺。
  - [x] 不增加第二份终端或浏览器状态 Store。
- 依赖：T003。

### T005 [P2] 系统权限、运行环境与支持入口

- 问题证据：通知、全部文件访问、投放区、运行准备、进程、日志和工具链能力分散；`StatusFragment`、`BridgeFragment` 没有正式导航入口，且含轮询或工程维护操作；`LogActivity` 只在 Manifest 注册。
- 解法：设置页只消费现有轻量快照并提供类型化管理入口；权限跳转 Android 系统设置；运行环境使用现有 readiness/runtime owner；日志和版本进入帮助页。旧状态/Bridge 页面只作为迁移材料，不原样嵌入设置。
- 验收标准：
  - [x] 权限状态来自现有权限拥有者并可打开正确系统页。
  - [x] 运行环境页不增加周期轮询或 UI 线程探测。
  - [x] 进程管理、日志和版本信息有可达入口。
  - [x] Manifest 中只有声明但没有完整产品链的权限不伪造设置项。
- 依赖：T003。

### T006 [P3] 本地化、可访问性与压力封口

- 问题证据：设置中心将新增多组固定文字、状态摘要和可点击行；长说明、横向色块和窄屏布局已有截断风险。
- 解法：完成中英文资源、内容描述、触控面积、长文案和窄屏适配；运行设置相关测试、Lint、本地化审计、压力热点扫描和构建。
- 验收标准：
  - [x] 中英文资源键一致，`MissingTranslation`、`ExtraTranslation`、`HardcodedText` 为 0。
  - [x] 所有可点击入口具备明确标题、状态摘要和可访问语义。
  - [x] 不新增整页刷新、渲染时重型探测或无取消轮询。
  - [x] 全量单测、Lint 和 Debug 构建通过。
- 依赖：T004、T005。

### T007 [P3] OnePlus 8T 真机验收

- 问题证据：设置属于用户可见交互，Robolectric 和静态检查不能证明窄屏、系统返回、语言切换和进程存活性。
- 解法：在默认 OnePlus 8T `3f8bbaad` 覆盖安装，逐页截图并验证中英文、权限返回、终端默认值、实验标识、后台恢复、FATAL/ANR 和压力路径。
- 验收标准：
  - [x] 中文、English、跟随系统三种语言路径可用。
  - [x] 设置首页和全部二级页面无截断、闪白、滚动丢失或错误返回。
  - [x] 权限/日志/进程入口可达，终端默认值双入口一致。
  - [x] 验收期间没有新增 FATAL、ANR 或输入超时。
- 依赖：T006。

### T008 [P3] 终端核心动作与发布范围确认

- 问题证据：真机控件树显示终端列表的新建按钮为可点击 `ImageButton`，但 `content-desc` 为空；终端列表和详情的图标按钮在 XML 中只有 36dp，低于标准触控面积。终端是一级主入口，这类差距比继续扩展设置条目更应先收尾。
- 解法：只调整终端列表/详情头部图标动作的触控面积和中英文语义，保持会话、输入、渲染和运行生命周期不变。汇总所有完成项后决定是否达到 `0.0.8` 发布门。
- 验收标准：
  - [x] 新建终端和返回会话按钮均不少于 48dp，控件树有准确双语内容描述。
  - [x] 终端空状态、新建、返回和已存在会话路径保持正常。
  - [x] 正式能力表、架构决定和用户文档与最终行为一致。
  - [x] 发布范围统一为 `0.0.8` 候选；获授权后执行版本修改、Release 构建、commit、tag、artifact 和 GitHub Release。
  - [x] 未经明确发布授权不改变远端或版本号。
- 依赖：T007。
