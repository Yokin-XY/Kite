# Kite 动态状态链路补全手册

## 目标

在稳定基线 `bc7ef77` 之上，审核并补全 Kite 的动态状态链路：状态拥有者写入事实并发信号，可见页面在一个合理帧周期内读取同一事实并局部更新，页面不可见时在恢复前台时校准。

## 红线

- 不新增平行状态库，不复制 `KiteResourceInstallStore` 或 `CardRunStore` 的事实。
- 不把轮询、整页刷新、重新导航、重建终端或重载 WebView 当作同步机制。
- 不增加资源、provider、机型单点特判。
- 不改变已经人工通过的浏览器登录协议和 CLI 原生交互。
- 优先修改纯投影、目标集合和可见控件绑定；避免扩大 `MainActivity` 的公共协议。

## T005 [P0] 审核动态状态拓扑

- 问题证据：资源安装、运行报告、浏览器回调等状态分别由不同 store 拥有；用户观察到部分页面需要二次点击才呈现终态。
- 解法：逐条记录“事件 -> 状态拥有者 -> 信号 -> 可见消费者 -> 恢复校准”，区分已闭环、延迟闭环和缺口。
- 验收标准：
  - [x] 覆盖资源安装/卸载/队列、CardRun、终端、Web/认证。
  - [x] 每个结论能指向真实代码入口。
  - [x] 只选择一到两个通用且低风险的实现缺口。
- 依赖：稳定基线 `bc7ef77` 已提交并通过完整单测、构建和 OnePlus 8T 验证。

## T006 [P1] 补全可见资源状态收敛

- 问题证据：`KiteResourceInstallStore.signals` 是 `StateFlow`，连续信号允许合并；当前可见投影在存在 `preferredResourceIds` 时只处理该子集，较早信号涉及的其他可见资源可能等到恢复前台或二次操作才校准。
- 解法：把信号视为“快照已变化”的脏信号；每次信号都从共享内存快照重投影全部可见资源，同时保留 preferred IDs 处理目标详情。
- 验收标准：
  - [x] preferred IDs 不再排除其他可见绑定或当前详情。
  - [x] 只更新可见卡片/详情，不读取网络、不整页重建。
  - [x] 有纯函数测试锁定合并信号场景。
- 依赖：T005。

## T007 [P1] 安装向导即时状态快路径

- 问题证据：安装向导收到 store 信号后，即使目录缓存已经存在，仍创建后台线程构建 UI 状态；失败、完成、卸载中等离散终态会多经过一次线程调度。
- 解法：目录缓存存在时，直接用内存目录、共享 plan snapshot 和 registry snapshot 在下一主线程周期局部更新；仅在目录尚未准备时保留后台回退。
- 验收标准：
  - [x] 已有缓存时不启动后台刷新线程。
  - [x] 失败色、状态文字、主操作和队列进度来自同一次快照。
  - [x] 无缓存时原有后台回退仍可用。
- 依赖：T005、T006。

## T008 [P0] 回归与真机验收

- 问题证据：状态同步修改横跨资源列表、详情、管理页和安装向导，需要证明没有引入整页闪烁、终端重建或状态倒退。
- 解法：运行目标单测和完整单测、构建 APK，并在 OnePlus 8T 上验证资源进入处理中、完成/失败投影、返回前台校准与无崩溃/ANR。
- 验收标准：
  - [x] `:app:testDebugUnitTest` 与 `assembleDebug` 成功。
  - [x] OnePlus 8T 安装成功，关键资源操作状态无需二次点击。
  - [x] logcat 无新崩溃、ANR 或 input timeout。
- 依赖：T006、T007。
