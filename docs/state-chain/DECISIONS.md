# Kite 动态状态链路决策

## ADR-S001 把信号解释为快照变脏，不把事件参数当完整事实

- 日期：2026-07-11
- 决策：`KiteResourceInstallStore` 和 `CardRunStore` 继续作为唯一状态拥有者。UI 收到信号后读取共享快照并更新可见控件；不复制事件参数形成页面本地状态。
- 理由：`StateFlow` 可以合并连续值，最新信号携带的 affected IDs 不保证包含被合并信号的全部 ID；共享 registry/plan/runs 快照才是完整事实。
- 影响：资源信号到达时允许重投影全部可见资源，但仍禁止整页重建和后台重型探测。preferred IDs 只用于补充目标，不再用于排除其他可见绑定。

## ADR-S002 安装向导优先使用内存快照即时绑定

- 日期：2026-07-11
- 决策：当资源目录缓存存在时，安装向导直接使用缓存目录和 store 快照构造当前 UI 状态；目录未准备时才进入现有后台回退。
- 理由：失败、完成、卸载中属于离散状态，不应因为无必要的线程切换而延迟；构造行状态只涉及小型内存集合和共享快照。
- 影响：不改变安装脚本、队列状态机或 CardRun 生命周期，不新增轮询，也不重建终端/WebView。

## ADR-S003 审核后不扩展其他动态状态机制

- 日期：2026-07-11
- 决策：浏览器回调、`CardRunStore`、终端、Web 显示面和资源更多页不新增监听器；资源管理页保留后台拓扑重算与局部区块 render key。
- 理由：浏览器回调已有 loopback/app redirect 原生入口，`CardRunStore.runs` 每次发布完整快照，终端刷新已有 single-flight/coalescing，Web/终端不应被资源状态触发重建；资源更多页本身不承载安装动作状态。
- 影响：本轮代码范围只包含可见资源目标并集、安装向导内存快路径和对应测试，不把一次稳定性收口扩大成 UI 架构重构。
