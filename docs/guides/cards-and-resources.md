# 卡片与资源

## 两种对象

### 首页卡片

首页卡片是一份可执行 Recipe。它描述名称、图标、启动方式和有序步骤。用户启动后，Kite 创建独立运行实例，并把报告、终端、网页、通知和底层进程绑定到该实例。

共享卡片目录：

```text
/sdcard/Download/Kite/cards
```

Ubuntu/PRoot 内对应：

```text
/exchange/cards
```

卡片可以由编辑器创建，也可以把 JSON 文件放入共享目录。新卡片协议见 [首页卡片 Schema](../reference/home-card-schema.md)。

### 资源卡片

资源卡片是 APK 内维护的资源清单，位于：

```text
assets/resources/<resource-id>/manifest.json
```

它描述资源来源、依赖、安装计划、验证方式、打开动作和可选首页卡片模板。资源首页布局位于 `assets/resources/home.json`。

## 卡片执行

稳定步骤类型：

- `shell`：执行非交互命令并形成 SH 报告。
- `terminal`：创建交互终端并发送预设输入。
- `open_web`：在运行实例中打开网页。
- `android_action`：调用由 Android 平台注册的动作。
- `native_capability`：调用结构化 Android 原生能力，不接受任意 shell。

X11 步骤属于实验能力，不建议用于正式交付卡片。

步骤按 JSON 中的顺序执行。每个步骤只能推进自己对应的状态，终端和网页显示面不能代替其他步骤完成。

## 资源安装

资源安装使用统一生命周期：

```text
resolve -> acquire -> install -> verify -> commit -> cleanup
```

- `resolve`：解析依赖和计划。
- `acquire`：下载、克隆或读取内置资产。
- `install`：执行渠道对应的安装动作。
- `verify`：验证命令、文件或运行条件。
- `commit`：验证成功后登记资源和受管命令。
- `cleanup`：清理临时文件；失败时恢复原版本。

受管 `download` 步骤可以声明 `maxBytes`。只有动作开头的单一静态 HTTPS 下载、`$install_root` 下安全目标和正数尺寸上限同时
满足时，Kite 才会用 Android 原生网络栈预取到资源缓存；后续安装、验证和更新锁仍走原资源事务。动态 URL、多镜像或缺少尺寸
上限时保持 PRoot，不会根据资源名称猜测。

网络失败、命令失败和验证失败都不能登记为安装成功。安装向导、资源详情和资源首页从同一安装事实投影状态。

系统管理组件在生成安装计划前会依据清单中的 `management.mode=system_component` 和
`managedCommands` 做一次后台事实收敛。命令已经真实可用但本地登记缺失或失效时，结果写回同一个安装 Store 并从计划中排除；命令仍缺失时才进入安装计划。该机制不识别 Git、Python、Node.js 等具体资源名称，也不改变普通自定义资源的安装语义。

获取动作被接受后先持久化 `PREPARING` 计划和安装向导实例，依赖解析完成后再切换为 `ACTIVE`。准备和执行阶段都显示可复入的“获取中”；普通返回只隐藏向导，取消或显式关闭才清理由该计划拥有的未完成状态。每个环境的计划变更按目标与计划代次串行校验，旧取消请求不能清掉之后创建的新计划。

## 资源依赖

资源清单可以声明：

- `provides`：该资源提供的能力。
- `base`：安装前必须满足的基础依赖。
- `defaults`：建议随资源准备的默认依赖。
- `extensions`：可以继续安装的扩展资源。

依赖解析结果由安装计划统一执行，页面不自行拼接安装命令。

## 打开与首页卡片

资源的 `actions.open` 可以返回一份 Kite Recipe。可见打开动作先由统一编排器创建或确认真实实例，再打开该实例的精确代次；通知权限等前置条件拒绝时不会留下半个显示任务。`homeCards` 可以声明用户选择“创建首页卡片”时使用的模板。模板创建后成为普通首页卡片，其运行状态不再由资源详情页面单独维护。

## 关闭语义

- 普通返回：只隐藏实例显示任务，保留同代运行或资源获取事实。
- 关闭手动终端或网页：只关闭目标窗口和它拥有的会话。
- 重置流程窗口：清理旧尝试并重新执行该步骤。
- 显式关闭实例或从最近任务划除：按 `instanceId + generation` 关闭该代实例全部流程窗口、手动窗口、终端和由它产生的进程；旧代关闭请求不能影响新代实例。
- 显式关闭安装向导：按同一身份取消所属资源计划并清理未完成事实；普通返回不取消。
- 卸载资源：执行资源卸载计划，不等同于关闭所有无关实例。
